# 嵌入式 C 核心

## 为什么国赛特别需要这些知识？

电子设计竞赛的 MCU 程序不是普通桌面程序。它需要处理硬件寄存器、实时采样、中断、DMA、通信和控制，因此必须理解 C 与硬件之间的边界。

## 1. volatile

`volatile` 用于告诉编译器：该对象的值可能在程序正常执行流之外发生变化，因此不能把它简单当成永远不变的数据缓存。

典型场景：

- 中断修改的标志位
- DMA 状态相关数据
- 内存映射硬件寄存器

注意：`volatile` **不是线程同步工具，也不是原子性保证**。

## 2. 位运算

```c
#define BIT(n) (1u << (n))

reg |= BIT(3);       // 置位
reg &= ~BIT(3);      // 清零
reg ^= BIT(3);       // 翻转
if (reg & BIT(3)) {  // 判断
}
```

要求：看到一个十六进制寄存器值时，能快速转换为二进制并判断对应位。

## 3. 环形缓冲区

典型用途：

```text
UART 接收
   ↓
中断/DMA
   ↓
环形缓冲区
   ↓
协议解析
   ↓
应用层
```

要求掌握：读指针、写指针、满/空判断、溢出处理。

## 4. 状态机

不要把复杂控制逻辑写成几十层 `if`。

```c
typedef enum {
    STATE_IDLE,
    STATE_RUN,
    STATE_ERROR
} State;
```

然后通过事件驱动状态转换。国赛中常见于：自动控制、通信协议、任务流程和故障处理。

## 5. 非阻塞程序

尽量减少：

```c
delay_ms(1000);
```

这种长时间阻塞。

更好的思路是使用定时器节拍：

```c
if (millis() - last >= 1000) {
    last = millis();
    Task_1s();
}
```

这样按键、显示、采样、通信和控制可以并行推进。

## 6. 模块化

推荐结构：

```text
Core/
BSP/
Drivers/
Algorithm/
App/
```

例如：

```text
BSP      → GPIO/UART/Timer
Drivers  → Sensor/Motor/Display
Algorithm→ PID/Filter/FFT
App      → 状态机与业务逻辑
```

## 7. 竞赛代码最低标准

- 编译警告尽量清零
- 不随意使用魔法数字
- 接口明确
- 关键参数集中管理
- 中断函数保持短小
- 不在中断中做耗时工作
- 明确缓冲区大小
- 对异常输入做边界处理
- 调试阶段保留必要日志
